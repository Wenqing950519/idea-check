# Report Template

## 目錄

1. 快速檢查格式
2. 完整審查格式
3. 評分尺度
4. Verdict 規則
5. 驗證實驗格式

## 1. 快速檢查格式

使用下列結構，保持精簡：

1. **Verdict**：`停止 / 擱置 / 先驗證 / 有條件投入`、信心高/中/低、一句關鍵理由。
2. **點子論點**：Customer、trigger、JTBD、pain、mechanism、measurable outcome、payer。
3. **最強訊號**：最多三項；標示事實或假設。
4. **最危險的洞**：最多三項；至少一項必須是需求或商業風險。
5. **替代方案地圖**：直接、間接、手動/服務、平台、開源、不作為。
6. **三個致命假設**：列出能推翻各假設的觀察。
7. **下一步**：三個低成本實驗，附成功與停止門檻。

## 2. 完整審查格式

### A. Executive verdict

- Verdict：`停止 / 擱置 / 先驗證 / 有條件投入`
- 信心：高 / 中 / 低
- 一句投資論點
- 一句反方論點
- 會改變 verdict 的最小新證據

### B. Idea thesis

以固定句型呈現客群、trigger、JTBD、現況、痛點、機制、結果與付款者。列出範圍與主要假設。

### C. Evidence ledger

| 主張 | 證據 | 事實/推論/假設/未知 | 支持或反駁 | 可信度 | 來源與日期 |
|---|---|---|---|---|---|

只保留 decision-relevant 證據。正文引用直接連到支撐主張的頁面。

### D. Reality check

- 客群與觸發事件
- 現行行為與替代成本
- 痛點、頻率、急迫性與不處理後果
- Why now
- 最強需求證據
- 最強反證

### E. Competitive landscape

先用類別地圖，再列重要代表：

| 替代方案 | 類型 | 客群/JTBD | 價格或成本 | 優勢 | 弱點 | 對本點子的含義 |
|---|---|---|---|---|---|---|

說明真正競爭基準、可能 wedge、10 倍優勢是否成立，以及平台吸收風險。

### F. Commercial engine

逐項回答 Customer、Pain、Frequency、Willingness to Pay、Switching Cost、Distribution、Acquisition、Retention、Expansion。再補：

- 建議價值度量與收費單位。
- 預算來源及銷售/採購摩擦。
- 單位經濟的已知、假設與未知；沒有資料時不要虛構 LTV/CAC。

### G. Strategy and adoption

- JTBD 切換力量：push、pull、anxiety、inertia。
- Rumelt kernel：diagnosis、guiding policy、coherent actions。
- ERRC：eliminate、reduce、raise、create。
- Beachhead、早期採用者及跨越主流市場所缺的 whole product。

### H. Second-order scenarios

| 情境 | 可能性 | 影響 | 領先指標 | 可逆性 | 對策 |
|---|---|---|---|---|---|

至少包含平台進入、免費化/API 變動、核心成本變動及成功後的競爭反應；若不適用要說明。

### I. Adversarial partner memo

- Feature vs product vs business vs company
- 10 倍優勢
- Distribution truth
- Moat / network effect / data flywheel 的成立或不成立
- Wedge-to-expansion 路徑
- 最大回報情境與最可能失敗原因
- 一個「即使產品做得很好仍會失敗」的原因

### J. Evidence-adjusted scorecard

| 維度 | 分數 0–5 | 證據強度 | 判斷理由 |
|---|---:|---|---|
| 痛點與急迫性 | | | |
| 問題頻率與價值實現 | | | |
| 已證實需求/付款意願 | | | |
| 替代方案缺口與差異化 | | | |
| Distribution 與 acquisition | | | |
| Retention 與 expansion | | | |
| 單位經濟/交付可行性 | | | |
| 平台、法規與依賴風險 | | | |
| 護城河與可防禦性 | | | |
| 團隊或執行適配 | | | |

不得只報總平均。先標出 hard constraint、最低分維度與低證據維度。團隊資料未提供時標記 N/A，不因未知給中間分。

### K. Fatal assumptions

| 排名 | 假設 | 類型 | 錯誤時的影響 | 現有證據 | 可推翻的觀察 |
|---|---|---|---|---|---|

### L. Validation plan

安排 1–3 週內可完成的實驗，先測致命且證據最弱的假設。不得把開發完整 MVP 當第一個需求測試。

### M. Final recommendation

重申 verdict、下一個 decision gate、停止條件，以及新證據出現時如何更新判斷。

## 3. 評分尺度

所有維度使用同一尺度：

- **0 — 反證明確**：可靠證據顯示主張不成立或存在 hard blocker。
- **1 — 很弱**：主要依靠願望，且已有顯著反證。
- **2 — 偏弱**：有合理故事或弱訊號，但關鍵行為未證實。
- **3 — 初步成立**：有至少一項具體支持證據，仍有重大未知。
- **4 — 強**：多項一致的行為、交易或可靠市場證據，風險可管理。
- **5 — 已驗證**：在相關客群與情境中反覆出現，並有付款、留存或同級強證據。

另列證據強度：

- **低**：推論、二手摘要、單一陳述或過時資料。
- **中**：多個一致訊號、官方資料或可觀察 workaround，但仍缺交易/留存。
- **高**：重複行為、付款、留存、第一方數據或多來源原始證據。

分數與證據強度是不同概念。例如一個風險可評為 4 分但只有低證據；這表示假說漂亮但不可靠。

## 4. Verdict 規則

- **停止**：存在難以移除的 hard blocker，或可靠反證顯示核心需求/商業模式不成立。
- **擱置**：可能有價值，但時機、資源、法規、平台或客群條件尚未成熟；列出重新啟動條件。
- **先驗證**：核心論點合理但致命假設仍主要靠推測；這應是多數早期點子的預設判斷。
- **有條件投入**：需求與商業關鍵點已有行為或交易證據，風險可透過明確里程碑管理。

不要因資料不足直接給「有條件投入」。資料不足通常降低信心並導向「先驗證」。也不要把「停止這個版本」誤寫為「永遠不要碰這個問題」；可提出更強的客群、wedge 或商業模式，但要說明它改變了哪些假設。

## 5. 驗證實驗格式

每個實驗都使用：

### 實驗：名稱

- **假設**：一句可被否證的主張。
- **風險類型**：需求 / 付款 / 通路 / 留存 / 技術 / 平台 / 法規。
- **受眾與樣本**：精確 ICP、招募方式、數量及避免偏差的方法。
- **最小測試**：不建造多餘功能的步驟。
- **承諾等級**：受訪、提供資料、安排內部利害關係人、pilot、LOI、預售、付款等。
- **時限與成本上限**：明確數字；依使用者資源調整。
- **成功門檻**：達成後允許哪個下一步。
- **失敗門檻**：達成後停止、改客群或改假設。
- **防假陽性**：如何避免禮貌性肯定、錯誤客群、低意圖流量或創辦人手工努力造成誤判。
- **決策更新**：結果如何改變分數與 verdict。

優先要求有成本的承諾。LOI 的強度取決於是否具體、由有權者簽署、包含時程/價格/條件，且接近真正採購；模糊的非約束支持信不能視為付款證據。
